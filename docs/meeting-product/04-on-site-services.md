# 现场服务：凭证、签到、酒店与餐券

## 1. 电子凭证与签到

### 用户侧

- 在“我的参会”展示动态二维码或条形码；
- 码每 30～60 秒轮换，截屏不可长期复用；
- 显示未开放、可签到、已签到、已过期等状态；
- 成功后展示签到时间、地点和后续服务提示；
- 可按配置展示座位、分组、胸牌领取点或接驳信息。

### 工作人员侧

Web 新增轻量现场核验页：摄像头扫码/手动输入、参会人信息、身份与状态、签到/撤销签到、异常提示、按点位统计。

### 服务端

- 新增参会凭证与签到流水；
- 凭证使用短期签名 token，不能直接暴露连续订单 ID；
- 签到必须幂等、防重放，重复扫描仅返回当前状态；
- 核验点、工作人员、设备、时间和撤销理由写入审计；
- 预留总签到、分会场签到、餐券核销等不同核验类型。

## 2. 酒店服务

### 用户侧

- 酒店列表展示地址、联系电话、入住/离店、房型、起价和剩余状态；
- 酒店详情展示图片、交通、房型、规则；
- 合资格用户可提交预订申请或选择房型；
- 我的参会展示酒店订单、确认状态、入住信息、分房结果和一键导航；
- 临近入住显示倒计时和联系酒店入口。

### Web 管理端

- 酒店、房型、订单、分房形成闭环；
- 配置报名资格、入住离店日期、单人限额、人工确认和取消规则；
- 显示库存、冻结、确认、剩余和超售预警；
- 分房完成后可通知参会者；
- 提供未确认订单、临近入住未分房等风险清单。

### 服务端

现有 `yc_hotel`、`yc_hotel_room`、`yc_hotel_order`、`yc_hotel_assign` 可复用；需补订单状态机、库存冻结、入住人关联、取消原因和当前用户私有查询接口。

## 3. 餐券与核销

### 用户侧

- 我的参会展示当日可用餐券：餐次、日期、地点、时段、状态；
- 使用时展示动态核销码；
- 已核销立即显示已使用；
- 未开放、过期、无资格时给出明确原因；
- 用餐前首页可根据用户资格提示即将开放的餐券。

### Web 管理端

- 餐券规则除名称、日期、配额外，应配置时段、核销点、适用票种和领取方式；
- 支持按身份自动发券、补发、作废、导出；
- 核销端支持扫码、手输、撤销（受权限和理由约束）；
- 实时查看已发、已用、剩余、异常核销。

### 服务端

现有 `yc_meal_ticket` 仅是规则定义。需新增用户券实例、核销流水和核销点；核销接口必须幂等，不能只依赖前端状态。

## 4. 验收

- 用户只能查看自己的凭证、订单、房间和餐券；
- 同一凭证/餐券不可重复成功核销；
- 签到或核销撤销有权限、理由和审计流水；
- 酒店库存与订单、分房数据一致，不允许超售；
- 网络异常时核验端给出明确提示，不伪造成功状态。
