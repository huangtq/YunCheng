# 原生业务模块目录与配置边界

## 1. 调研结论

对参考会议站点的入口跳转进行逐项解析后，栏目名称不能用于判断实现方式。同名“会议议程”可落到富文本内容页，也可进入独立日程系统；“酒店预定”和“学分须知”在样本中都是内容页；照片直播和会务支持则是外链。

Web 配置必须先选择目标类型，再选择具体目标，禁止依据标题自动绑定模块：

| 目标类型 | 适用内容 | Web 配置 | 移动端职责 |
| --- | --- | --- | --- |
| `content` | 邀请函、通知、须知、组织机构、学分说明、酒店说明、静态议程 | 选择内容、可见范围、入口素材 | 统一内容页 |
| `module` | 日程、嘉宾检索、我的参会、签到、酒店服务、餐券、展商 | 选择受控模块和显示条件 | 原生列表、详情、状态和操作 |
| `file` | PDF、议程册、附件 | 选择受控资料、下载权限 | 预览、下载或打开指引 |
| `map` | 会场、注册处、酒店、服务点 | 选择 POI/会场，不填裸 URL | 展示说明并发起地图导航 |
| `external` | 照片直播、第三方会务、未接入的问卷/考试 | `https` URL、有效期、打开方式 | WebView 或外部浏览器 |
| `group` | 大会议程、会务服务等分类 | 标题、子入口、展开方式 | 展开子入口，不直接跳转 |

参考站的路由验证：`program` 是独立日程模块，`speaker` 是讲者查询，`traffic` 是地图模块，`user?reg` 与 `user?user` 是登录后报名/个人中心；调查问卷有公开 `survey` 与按用户资格执行的 `survey-user` 两种路由。照片直播和会务支持是外部链接。

## 2. P0 原生模块

### 2.1 日程 `schedule`

**用户体验**：按日期进入时间轴，按会场、主题或分会场筛选；突出正在进行和下一场；日程详情提供主题、开始结束时间、讲者/主持/讨论嘉宾、会场、关联资料和导航。没有开放排期时显示明确业务空状态，而不是空白页或富文本替代。

**Web 配置与数据**：入口仅选择模块；日期、会场、主题、日程和嘉宾由业务管理页维护。首页可配置“下一场”卡片和默认筛选范围，但不能在首页 JSON 中复制日程。发布校验检查至少一条可公开日程；若某入口只代表一个分会场，应配置 `venueId` 或 `topicId` 作为模块上下文。

**现有复用与缺口**：复用 `yc_venue`、`yc_topic`、`yc_schedule`，现有后台已支持会场、主题、日程和讲者名单。需要把逗号分隔的讲者姓名逐步替换或映射为嘉宾关联；增加日程详情、状态、公开开关、资料/直播关联、变更说明与冲突校验；移动端不能继续只用通用卡片列表。

### 2.2 嘉宾/讲者检索 `guest`

**用户体验**：姓名搜索，按主题、机构、角色筛选；列表展示头像、姓名、机构和职务；详情展示简介、公开标签及关联场次，能跳转日程。参会嘉宾的手机号、身份证、行程、劳务和酒店安排绝不向公众下发。

**Web 配置与数据**：入口选择模块，可配置是否显示搜索、筛选维度和重点嘉宾推荐。嘉宾公开资料与会务管理资料必须分层：头像、姓名、机构、职务、简介和公开标签可以下发；联系方式、证件、行程、劳务费仅供后台授权角色。

**现有复用与缺口**：复用 `yc_guest` 与已有日程中的主席/主持/讲者/讨论名单。当前后台有嘉宾库和专家任务汇总，但移动端接口直接下发整个实体且展示手机号，必须改为公开 DTO；需新增结构化嘉宾-日程多对多关联，不能长期依赖姓名匹配。

### 2.3 会场与 POI 导航 `venue` / `nav`

**用户体验**：会场详情显示楼层、开放状态、说明和关联日程；POI 用于注册处、酒店、餐厅、接驳点、服务台等。用户从首页、日程或服务页进入后，可查看位置说明，再唤起系统地图或高德/百度导航。

**Web 配置与数据**：地图入口只选择会场或 POI；后台维护分类、地址、经纬度、电话、服务时段、封面和状态。无有效坐标时禁止发布为“导航”入口，但可以作为内容说明展示。

**现有复用与缺口**：复用 `yc_venue`、`yc_activity_nav`。现有导航点已有地址、坐标、电话和封面；需补 POI 分类、会场与 POI 的关系、开放/拥挤/关闭状态和用户侧详情。不能把第三方地图 URL 作为主数据。

### 2.4 我的参会 `my-attendance`

**用户体验**：这是登录用户的私有服务中枢，不是公共内容页。展示报名状态、身份、电子凭证、签到、待办、下一场、酒店/餐券/资料和本人消息；未登录时进入现有微信授权流程。

**Web 配置与数据**：首页只配置入口文案、展示条件和是否主推。运营不能在入口中配置个人数据；服务端基于当前用户和活动汇总状态。报名仍复用现有流程，不以参考站登录表单为改造目标。

**现有复用与缺口**：复用 `yc_apply_order`、微信登录和现有报名页。现状只有报名/取消和签到字段，需按 [报名与我的参会](02-registration-and-my-attendance.md) 增加审核、凭证、权益、服务任务和私有聚合接口。

## 3. P1 原生模块

### 3.1 酒店服务 `hotel`

酒店说明可用内容页；只有提供房型选择、预约、订单状态、分房结果时才启用原生酒店模块。原生模块要求登录，并由服务端根据报名身份决定资格；展示酒店、房型、库存状态、入住离店、订单和房间分配。库存冻结、确认、取消和分房属于服务端状态机。

现有 `yc_hotel`、`yc_hotel_room`、`yc_hotel_order`、`yc_hotel_assign` 可以复用，但要补资格、库存冻结、入住人关联、用户归属和私有查询；首页不能仅依据“酒店表有数据”对所有匿名用户展示可预订入口。

### 3.2 餐券与签到 `meal` / `checkin`

餐券规则、签到点和核验配置属于后台数据；用户侧展示的是本人券实例与动态凭证。入口必须要求登录，并由服务端返回“未开放、无资格、可使用、已使用、过期”等状态。扫码/手输核验、重复扫描、撤销均必须幂等并审计。

现有 `yc_meal_ticket` 仅覆盖规则定义，不能直接作为用户餐券列表。签到复用订单的现有字段作为兼容数据，但新凭证和核验流水应独立建模。

### 3.3 展商 `exhibitor`

当需要名称/品类搜索、详情、展位导航和收藏时使用原生模块；只有宣传文案时用内容页。公开 DTO 只包括品牌、封面、品类、展位、公开资料和外链；联系人与留资必须有独立授权。复用 `yc_exhibitor`，补类别、展区 POI、公开开关、详情资料和收藏统计。

### 3.4 通知与回放 `notice` / `replay`

静态通知可作为内容入口；需要未读、身份范围、优先级、频控和事件触发时使用原生通知模块。回放可作为日程详情的受控资源，也可由会后首页卡片主推。两者都不得通过首页富文本绕开用户范围和有效期判断。

## 4. 外部能力与不纳入默认原生模块的功能

照片直播通常是第三方相册，使用 `external`；会务支持同样是外链。公开满意度调查可作为 `survey` 外链或后续原生问卷，针对报名用户的二次确认属于私有 `survey-user` 流程，必须绑定用户、资格、答题有效期和幂等提交。学分说明默认是内容页；学分申报、学时核验、证书下载需要独立立项，不能以“学分须知”入口名暗示已经实现。

## 5. Web 配置界面要求

入口编辑器采用两步：先选 `group/content/module/file/map/external`，再显示对应字段。选择 `module` 时只能从模块能力注册表中选取，并根据模块展示上下文配置，例如日程的会场/主题范围、嘉宾的公开筛选项、酒店的资格开关。选择 `content` 时只选择内容对象；选择 `external` 时校验 `https`、有效期和打开方式；选择 `map` 时只允许选择有有效坐标的 POI。

发布校验必须验证目标存在、已发布且对目标人群可见。模块没有数据时默认隐藏，但运营可选择“显示为即将开放”；私有模块不得出现在匿名首页的可用状态中。

## 6. 验收

- 同名栏目可以被正确配置为内容、模块或外链，移动端按目标类型打开，不依赖标题猜测；
- 日程、嘉宾、导航和我的参会有各自的列表/详情/状态体验，不共用通用模块卡片页；
- 公开接口不返回嘉宾手机号、证件、行程、劳务、房号、订单或用户券；
- 未开放或无数据的原生模块展示明确状态，发布校验阻止失效目标；
- Web 编辑入口后，首页、内容页侧栏和二级分组导航保持同一版本的一致性。
