# 会议产品实施计划

本目录把 `docs/meeting-product/` 的目标需求拆成可执行任务，替代 Notion 计划和任务库。每个任务以可独立合并、可验证的交付物为单位；状态仅在实际完成并验证后更新。

## 执行原则

- 产品边界以 [会议产品文档集](../meeting-product/README.md) 为准；实施任务不得用旧 UI 或旧接口行为反向降低需求。
- 旧代码是迁移输入，不是设计约束。允许替换通用模块页、扁平配置 DTO、分散前端判断和不安全公开接口；仅保留迁移期所需的兼容接口与数据转换。
- 先建立服务端协议、公开 DTO、版本化数据和发布校验，再实现 Web/H5 页面。前端不得自行推断资格、库存、可见性或模块状态。
- 每项任务都应同时说明数据迁移、权限和验收；涉及匿名接口时先审查字段最小化。
- Web 使用 `pnpm`；服务端与 Web 均依赖现有热更新，优先通过浏览器或接口验证，不执行无关全量构建。

## 任务状态

`待开始`：依赖未就绪或尚未开发。<br>
`进行中`：已经开始修改，尚未满足验收。<br>
`已完成`：代码、迁移与对应验证均已完成。<br>
`阻塞`：需要产品决策、外部凭据或不可用的依赖。

新开发任务从 Phase 1 按依赖顺序领取；任务完成后更新状态、提交链接、验证证据和未解决风险。
