# Phase 2：P1 现场服务闭环

## 目标

将已报名用户从“报名成功”带入可核验的现场服务：私有参会中心、动态电子凭证、可审计签到、酒店服务、餐券和重要通知；后台能够在不暴露个人数据的前提下处理现场异常。

## 任务

### P1-01 电子凭证与签到

**状态：进行中**

- 新增 `yc_attendee_pass` 与 `yc_checkin_log`，电子凭证不使用连续订单 ID。
- 用户侧凭证为 60 秒 HMAC 签名 token；后台按凭证、会议、幂等键核验并记录流水。
- 已实现“我的参会”私有聚合接口和后台手输核验页。
- 待完成：二维码呈现、撤销签到、核验点统计、真实数据库迁移与并发验收。

### P1-02 酒店服务

**状态：待开始**

- 在既有酒店/房型/订单/分房模型上增加库存冻结、用户私有订单读取、资格与取消规则。
- 公开首页不暴露酒店订单、房号、价格规则或其他用户资料。

### P1-03 餐券与核销

**状态：进行中**

- 以餐券规则派生用户券实例和核销流水；不可把 `yc_meal_ticket` 规则表直接给用户端。
- 复用凭证核验模型，但餐券必须有独立资格、时段、状态和撤销审计。
- 已新增用户餐券实例、核销流水、私有餐券接口和后台核销接口；待补发券工作台与动态凭证严格签名校验。

### P1-04 通知与运营驾驶舱

**状态：待开始**

- 新增会议通知、阅读记录与高优先级投放。
- 提供报名、签到、酒店、餐券的汇总和异常清单，不在驾驶舱传播个人明细。

## 验收

- 用户只能访问自己的凭证、签到与服务状态；凭证过期、作废、跨会议均被拒绝。
- 同一凭证同一幂等键不重复签到，重复请求返回原结果；流水包含操作人、设备和核验点。
- 酒店与餐券上线后，库存/核销必须一致且可审计。
